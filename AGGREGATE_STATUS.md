# Aggregate backend status

What the aggregate-bounding backend (design/AGGREGATE_BOUNDING.md) achieves on a low-constraint
MINLPLib subset, beside `gams_solve` on the same instances and the same iteration budget.
Generated by `tools/aggregate_status.py`; edit that, not this.

- Instances: **20**, chosen for zero or very few inequality constraints (§12)
- Iteration budget: **1000** per run; wall-clock cap **300 s**
- Reference bounds: quoted from `MINLP_STATUS.md`, which records their retrieval date
- Measured at: `cff66b7-dirty`

## Reading the table

**Ref primal / Ref dual** are the published bounds, in the instance's own sense. **Agg** and
**gams** columns are this run's own. For a `min` row a dual is a lower bound, so *larger*
is tighter; for `max` it is an upper bound and smaller is tighter. The **Better dual**
column names the backend whose dual is tighter, which is the quantity stage 6 exists to
compare — the primal is reported but is a sampler result rather than a property of the
bounding scheme.

A run that reports `converged` has had its dual collapsed onto its incumbent by
`finalise_bounds`, so its dual is sound only to within the run's tolerance. A converged
dual a hair past the published primal is that, not an unsound bound; anything past it by
more than the tolerance is listed under Inversions below and is a bug report.

Both duals are capped at the published primal before being compared: a run cannot be
credited with beating the true optimum, which it would otherwise be whenever the
tolerance let its converged dual overshoot. `_both vacuous_` marks a row where neither
backend came within a factor of 1e6 of the optimum — reachable when a variable took
the frontend's 1e6 default bound, and not a result worth ranking.

**Agg iters** is set only where a row did *not* run at the budget in the header — a row
carrying a number there was given more (or fewer) iterations than the backend it sits
beside, and its comparison is not like-for-like. **pending** is the frontier size the run
ended with, which is §2.1's whole claim in one column.

## Reproducing a row

```sh
cmake --build build/dev -t aggregate_solve
./build/dev/aggregate_solve ../minlplib/gms/<instance>.gms 1000
```

Unlike `MINLP_STATUS.md`'s `--policy=` cell, this is the whole command: the aggregate
backend's shape comes from `--branch-factor` and `--partition-budget`, both of which
default to the values these runs used (`k = 4`, `N` fitted to free device memory).
